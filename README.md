# Fc-Construct's MIRE Squiglink

An open-canal **MIRE (Microphone-in-Real-Ear)** frequency response database and interactive visualization tool for over-ear headphones, maintained by **Fc-Construct**. 

---

## 1. Project Overview & Vision 

This application is customized specifically for **open-canal MIRE headphone acoustic measurements**, modifying coupler-focused systems and introducing dedicated seating, channel, and variant controls.

* **Microphone-in-Real-Ear (MIRE)**: Captured using miniature probe microphones placed at the entrance of Fc-Construct's unoccluded ear canal while wearing over-ear headphones, incorporating real Head-Related Transfer Functions (HRTF).
* **Seating Variance**: Accounts for pad seal and placement variations by measuring multiple distinct seatings per ear (`L1..L3`, `R1..R3`) as well as seal variations (e.g., eyeglasses vs. clean seal).

## 2. Core Architecture & Upgrades Over Squiglink

### 1. Standardized IEC 60263 25 dB/decade Acoustic Plotting
* **Acoustic Plotting Standard**: Standardized the live `#fr-graph` SVG to strictly follow the IEC 60263 25 dB/decade acoustic plotting standard (on the default 40 dB Y-axis scale).
* **Precise Plot Dimensions**: Set `W0 = 800` (with horizontal padding `l: 36`, `r: 14`, giving plot width `W = 750` across 3 decades from 20 Hz to 20 kHz, resulting in an exact `250.0` units/decade). The vertical 40 dB plot height is set to `H = 400.0` (`10.0` units/dB, exact IEC 25 dB/decade proportions) inside a `800 × 434` viewbox (`pad.t = 8`, `pad.b = 26`).
* **Clean Y-Axis Formatting**: Formats outside-left Y-axis ticks as `0 dB |` for clarity.

### 2. Modular 4K 16:9 Export & Direct Actions (`export4k.js`)
* **Dedicated Export Module**: Encapsulated screenshot and save logic inside a dedicated modular component (`export4k.js`), keeping `graphtool.js` clean and robust.
* **Strict WYSIWYG 4K Framing**: When clicking **Save** or **Screenshot**, clones the active `#fr-graph` SVG cleanly (preserving exact active curves, line styles, labels, and theme variables) and centers it inside a padded **4K 16:9 (`3840 × 2160`)** canvas with clean outer margins and zero distortion of the 25 dB/decade proportions.
* **Direct Actions**: **Save** immediately downloads to a `.png` file with an autogenerated filename; **Screenshot** copies directly to the clipboard with zero pop-up interruption.

### 3. Auto-Generating & Editable Graph Headers (`graphHeader.js`)
* **Dynamic Auto-Titling**: Automatically inspects active non-target headphones, joining them with `" vs. "` while suppressing consecutive repeated brand names (e.g. `Sennheiser HE1 vs. HD 600`) and keeping each model token intact across wrapped lines, or defaulting to blank if no headphones are shown.
* **Live Inline Editing**: Title and subtitle headers are rendered as interactive input fields directly on the graph header, allowing immediate in-app adjustments before saving or exporting.
* **Standardized Subtitle**: Defaults to `"1/6 Smoothing | Fc-Construct DF-HRTF | MIRE"`.

### 4. Top-Docked Frequency Region Guide & Space-Saving Sidebar Layout
* **Top Frequency Strip**: Relocated frequency response region tutorial buttons (`Sub bass` through `Treble & Air`) flush above the graph plot box (`div.graph-sizer`), aligned pixel-for-pixel with logarithmic X-axis frequency spans (displayed on desktop and mobile landscape).
* **Space-Saving Sidebar Header**: Reclaimed vertical screen space by moving the app title (`Fc-Construct`) and `Reviews` link directly into the top of the `350px` left sidebar grid (`header.header`), allowing the graph to start at the top of the viewport.
* **Clean Mobile Navigation**: Removed mobile portrait clutter (e.g. modal backdrop overlays) while retaining full progressive disclosure and mobile landscape support.

### 5. Color-Blind Safe Color Palette and Consistency 
* **Color-Blind Safe HCL Palette**: Built with 12 perceptually uniform HCL hues calibrated to avoid red-green confusion and ensure high legibility.
* **Anchor Color Stability**: The primary active headphone is always assigned Index 0 (Cobalt Blue). Remaining models receive a fixed, high-contrast sequence and dynamically retain their assigned color slots when models are deselected.
* **Distinct Channel Lines**: Right channel is styled as a solid line (`─ R`) and Left channel as a dashed line (`- - L`), matched with explicit legend prefixes. Reference targets use fine dotted lines (`2, 4` at 55% opacity) to prevent clashing with left-channel dashes.

### 6. Data Ingestion, Inventory, Caching & Pre-loading Pipeline
* **Hybrid Source of Truth (`phone_book.json`)**: Preserves manual curation, custom ordering, and unique model/variant naming hierarchies without algorithmic misclassifications.
* **Automated Python Sync (`update_phonebook.py`) & Static File Inventory (`file_inventory.json`)**:
  * Scans `/data/` for raw measurement `.txt` files (supporting compact and spaced channel/seating naming conventions).
  * Non-destructively merges new measurement prefixes into `phone_book.json` while keeping existing manual entries intact, and dynamically nests parenthesized modes (`(ANC 100)`, `(Bass)`, etc.) alongside `G` / `Glasses` tags in either order (`Model G (Mode)` or `Model (Mode) G`), sorting each `(Mode)` directly before `(Mode) Glasses`.
  * Automatically generates `file_inventory.json` mapping every model/variant prefix directly to its exact measurement files on disk, completely eliminating runtime 404 probing requests.
  * Automatically mirrors updated data and inventory files to `/public/` for local sandbox development.
* **Runtime Zero-404 Pre-loading, Caching & In-Flight Deduplication (`graphtool.js`)**:
  * **Dual-Layer In-Memory Caching (`rawFileCache` & `parsedResultCache`)**: Raw `.txt` files and parsed channel arrays are cached in memory for instant 0ms re-fetches and switches.
  * **Idle Background Prefetching**: Automatically pre-loads all library models and variants sequentially during browser idle time (`requestIdleCallback`) starting 2 seconds after page load.
  * **Direct Inventory Lookup**: Consults `file_inventory.json` to fetch only confirmed files, eliminating network 404 errors.
  * **In-Flight Request Deduplication (`inFlightLoads`)**: Selecting a model currently pre-loading in the background attaches directly to the active `Promise`, displaying curves instantly upon resolution without duplicate network requests.

### 7. Unified Sidebar Navigation, Inline Pinning & Theme Compatibility

### 8. Smoothing Detection
* **Header Metadata Inspection**: Reads header comments in exported REW text files upon load.
* **Warning Indicators**: Non-standard or missing smoothing (e.g., `1/12 octave` or `None`) displays a subtle `⚠️` warning badge with a descriptive tooltip, while standard `1/6 octave` acoustic measurements remain badge-free.

### 9. Dynamic Custom Reference Views
* **Live Preference Tuning**: Adjusting Tilt (dB/Oct), Bass Shelf, Treble, or Ear Gain dynamically generates a custom reference target.
* **Persistent Custom Presets**: Save custom configurations as presets numbered from the lowest available slot (`CUSTOM 1`, `CUSTOM 2`, etc.), double-click in-place to rename, or delete individual presets (`×`). Saved views persist across page refreshes in `localStorage` and preserve filter parameters in shared URLs.
* **Presets**: Defaults to `10 dB downwards tilt` (-1 dB/Oct slope) on load, with one-click switching to flat `Fc-Construct DF-HRTF`.

### 10. Calculate Functionality
* **Band Selection Brush & Frequency Guide**: Click the **`∫ calculate`** tool button to browse frequencies cleanly via an upper-grid vertical `Hz`/`kHz` hairline, then drag across any range ($f_0 \rightarrow f_1$) on the graph canvas.
* **Screen-Aligned Delta (`Δ`) Metrics**: Computes log-frequency-weighted absolute decibel differences strictly matching what is plotted on screen—showing `Δ L/R` (when both L & R channels are visible), `Δ Models` (for two visible models), and `Δ avg vs. Ref` / `Δ vs. Ref` (color-coded per model up to 4 visible models).
* **Badge Placement & Tool Reset**: Centers the dynamically sized badge around the `+10 dB` grid line cleanly below the header, stays mutually exclusive with **Inspect**, and automatically resets when adding or removing headphone models.

### 11. Adaptive Multi-Column Label Layout & Logarithmic Tilt Math
* **Dynamic Multi-Column Label Stacking**: Automatically stacks active model curves into neat columns (up to 8 models in the bottom-left zone; 9+ models spilling into the top-left open whitespace zone). This allows for up to 16 models to be labeled nicely.
* **Precise Text & Width Measurement**: Computes rendered text bounding box widths (`getBBox().width + 14px`) dynamically to prevent overlaps or awkward gaps, with automatic font-size downscaling (`12.5px` $\rightarrow$ `11px` $\rightarrow$ `10px`) for large model counts.
* **SVG Layer Isolation**: Separates static curve labels (`g.labels-layer`) from interactive overlays (`g.tools-layer`), entirely eliminating label jumping when toggling Inspect or Calculate tools.
* **Logarithmic Tilt Representation Note**: The $-1\text{ dB/Octave}$ tilt uses logarithmic scaling (`tilt * Math.log2(frequency / referenceFrequency)`). While a symmetric $\pm 5\text{ dB}$ split between 20 Hz and 20 kHz requires the reference pivot to be at the geometric mean ($f_{\text{geometric}} = \sqrt{20 \times 20,000} \approx 632.46\text{ Hz}$), the target curves anchor at the industry-standard **1 kHz (1000 Hz)** reference point, yielding $+5.64\text{ dB}$ at 20 Hz and $-4.32\text{ dB}$ at 20 kHz.

### 12. Inspect Tool Stacked Readout & Graph Box Bounding
* **Consistent Stacked Ordering**: Renders live cursor readouts as a unified vertical block locked in deterministic top-to-bottom order (**Reference View** on top, followed by active headphone **R** and **L** channels) so labels never swap positions when curves cross.
* **Graph Box Bounding Math**: Computes the exact rendered SVG bounding box (`getBBox()`) of active inspection labels and clamps the container's position inside plot padding boundaries (`pad.l` to `pad.l + W` horizontally, and within the plot frame vertically) so labels never overflow at `20 Hz` or `20 kHz`.

### 14. Unified Channel & Seating Dual-Pill Controls
* **Three Independent Semantic Pills**: Split into **`Left`**, **`Right`**, and **`L+R`** control pills for granular multi-channel management.
* **Dual-Action Pill Architecture**:
  * **Text Button**: Clicking the text directly (e.g. `LEFT: AVG` $\rightarrow$ `LEFT: ALL`) cycles between average view and all seating curves.
  * **Chevron Dropdown (`▾`)**: Opens a themed native dropdown to select specific individual seatings (`L1`, `L2`, `R1`, `Seat 1`, etc.), `AVG`, or `ALL`.
* **Eye Visibility Toggle (`👁` / `⌣`)**: Each pill features an integrated eye toggle icon to independently show or hide that channel/variant.
* **Non-Exclusive Channels**: Channels are not mutually exclusive; users can show `Left`, `Right`, and `L+R` averages simultaneously to visualize asymmetry and channel skews.
* **Hover Isolation & Average Dimming**:
  * Hovering over any individual channel pill isolates and highlights only that channel's curves on the graph (`.highlight` class).
  * When `L+R` (AVG) is active, `Left` and `Right` curves automatically dim to 45% opacity to emphasize the primary average curve. Hovering over the `Left` or `Right` pill instantly restores their opacity on hover.
* **True Seating Metadata & Adaptive Missing-Channel Pills**: Preserves actual measurement seating numbers from filenames (`L3`, `R3`, `L4`, etc.). Missing channels remain visible as deselected, grayed-out disabled pills (`Left: —` / `L + R: —` with empty chevron dropdowns) so UI layout stays stable while unavailable controls cannot be toggled.
* **Centralized Channel & Seating Auto-Switching**:
  * **Single-Model Default (`L + R` / `AVG`)**: Displays **`Left` + `Right`** when viewing one headphone on its own, and automatically collapses both the headphone and its EQ curve to **`L + R AVG`** when EQ is engaged without per-ear `Left`/`Right` splits.
  * **Multi-Model Comparison (`R AVG` / Single-Channel Sync)**: Automatically switches unpinned, non-overridden curves to **`R (AVG)`** when 2 or more headphones/variants are plotted—or matches the active single-side channel and seating number (e.g., `R3` $\leftrightarrow$ `R3` or `L3` $\leftrightarrow$ `L3`) when comparing against a single-channel measurement—and cleanly restores **`L + R`** as soon as the comparison drops back down to one model.
  * Any manual change to a pill's visibility or seating acts as a per-curve override until that model is removed.
* **Integrated Offset Control**: `OFFSET [ 0 ]` control integrated cleanly into the model control row.
* **Channel Imbalance Detector Disabled for MIRE**: Updated `hasImbalance()` to average all Left seatings against all Right seatings (instead of comparing raw channel slots), and disabled the automatic `⚠️` imbalance warning badge (`graphtool.js` / `phoneTable.js`). Because open-canal human-ear MIRE measurements naturally exhibit minor broadband L/R asymmetry across ear anatomy and pad fit without a coupler rig reference, users can directly inspect plotted `Left` vs. `Right` curves and quantify band differences via **Calculate** (`Δ L/R`).

### 16. Unified Parametric Equalizer, Auto-Saving Profiles & Real-Time FFT Spectrum (`eqPanel.js`)
* **8-Band Standard PEQ Rack (`48 kHz` RBJ Biquad Engine)**: Pre-initialized with an 8-band studio default layout (`60 Hz LSQ Q=0.71`, `200 / 500 / 1000 / 3000 / 6000 / 8000 Hz PK Q=1.0`, `10000 Hz HSQ Q=0.71` in `0.1 dB` gain steps) evaluated via second-order RBJ biquad math (`equalizer.js`), expandable up to `20` bands.
* **Session-Driven Editor & Auto-Saving Custom EQ Profiles**:
  * **Unified EQ Session State**: Filter scopes (`L+R`, `Left`, `Right`), channel balance, bypass state, target headphone selector, on-graph overlay, and plotted EQ curves are governed by a single session state so sidebar edits, graph handle drags, and plotted curves remain synchronized.
  * **Custom EQ Profiles (`CUSTOM EQ 1`, `2`, ...)**: Save any active EQ setup (linked to a headphone or as a standalone Sandbox EQ) as a persistent preset pill numbered from the lowest available slot. Click a pill to load/focus it in the editor or deselect it back to defaults, double-click to rename, or delete (`×`) to remove it and cleanly clear the rack.
  * **Seamless Auto-Save & Safe Reset**: While a Custom EQ pill is focused, adjustments to bands, channel scopes, balance, or target headphone auto-save back to that preset in place. Clicking **Reset** clears the editor rack and deselects the active pill first so saved Custom EQ profiles are preserved intact.
* **Additive 3-Scope Channel Architecture (`L+R`, `Left`, `Right`)**:
  * Maintains three persistent filter banks—shared **`L+R`** plus independent **`Left`** and **`Right`** trim racks—computing true additive stereo chains (`L = (L+R) + Left`, `R = (L+R) + Right`) for both plotted curves and live audio playback.
  * Automatically coordinates with channel auto-switching: single-model EQ comparisons collapse cleanly to **`L + R AVG`** and expand to split **`Left`/`Right`** channels whenever per-ear trims are active, while 2+ model comparisons stay aligned on **`R (AVG)`**.
  * Displays both **Export Peak `Pre-amp`** (worst-case headroom for Equalizer APO / external hardware) and **Live `Auto-Gain`** (psychoacoustic A/B trim), and supports scope-aware imports/exports (Equalizer APO Parametric TXT and 127-band Wavelet Graphic EQ).
* **ITU-R BS.1770-4 K-Weighted Loudness-Matched A/B & Click-Free Bypass**:
  * **Always-On Perceptual Auto-Gain**: Evaluates active Left/Right filter transfer curves against 48 kHz **ITU-R BS.1770-4 K-weighting** over a 128-point logarithmic (`1/f` pink) frequency grid so **`Bypass`** matches perceived loudness rather than biasing toward boosts.
  * **Volume-Aware Shared Safety Ceiling**: Leaves dry/wet playback untouched while boosts stay within current monitor headroom; if boosts exceed digital headroom, a shared safety gain attenuates **both** Dry and Wet paths equally to prevent `0 dBFS` clipping without compression or loudness jumps.
  * **Parallel Dry/Wet Graph & In-Place Ramping**: Keeps Dry and stereo Biquad Wet paths wired in parallel and ramps `Bypass` crossfades and live filter edits smoothly via Web Audio `setTargetAtTime` without switching clicks.
  * **Built-In `ⓘ` Architecture Tooltip**: Hovering or clicking `ⓘ` next to **Parametric Equalizer** summarizes perceptual auto-gain, shared clipping protection, and `Pre-amp` export headroom.
* **Color-Matched `EQ Curve` Overlay & Interactive On-Graph Handles (`g.eq-handles-layer`)**:
  * **Color-Synced Transfer Overlay**: Renders the active scope's combined transfer function centered on the graph reference (`yCenter`), remaining hidden until EQ is engaged and dynamically adopting the active EQ curve's color with translucent shading (dimming visually when bypassed).
  * **Equalizer-Scoped Direct Manipulation**: Draggable numbered filter nodes (`1–8+`), single-band preview curves, and a compact floating `Hz | Gain | Q` readout appear only when the **Equalizer** tab is open and EQ is active, yielding automatically when **Inspect** or **Calculate** are active (and excluded from 4K PNG exports).
  * **Intuitive Double-Click Workflow**: Double-clicking the graph while on the Equalizer tab with the overlay hidden engages the EQ overlay and snaps the nearest baseline band (`1–8`) to the cursor position; once active, double-clicking empty graph space adds a new peaking band (`9+`), double-clicking any baseline handle (`1–8`) resets it to default, and double-clicking any added handle (`9+`) deletes it (tracking original band identity even after sidebar sorting). Supports 2D dragging (`Shift` for 4× fine control), mouse-wheel `Q` adjustment, and bidirectional sidebar row highlighting.
* **Real-Time Dual-Tap `16384`-Point `1/12`-Octave FFT Spectrum Analyzer (`#fft-canvas`)**:
  * **Parallel Stereo Web Audio Chain**: Routes built-in (`Pink Noise`, `Scarlet Fire`), user-uploaded tracks, and a `20 Hz–20 kHz` logarithmic Tone Generator through independent L/R Web Audio `BiquadFilterNode` chains and an attenuation-based stereo balance stage (never applying positive digital boost gain).
  * **Pre-Fader Metering**: Dual `16384`-point `AnalyserNode` taps sample both **Pre-EQ** and **Post-EQ** signals prior to the master monitor `volumeNode` (default `70%`), keeping spectral levels independent of listening volume.
  * **Power-Accurate Logarithmic Binning**: Sums fractional-bin linear power across `120` logarithmic `1/12`-octave bands (`20 Hz–20 kHz`) with sub-bin low-frequency interpolation so broadband pink noise renders flat across the spectrum.
  * **Configurable Display Modes**: Renders onto a hardware-scaled `<canvas id="fft-canvas">` underlay behind `#fr-graph` with selectable **Bars** (default high-density micro-bars) or smooth **Wave** visualization, **Post-EQ / Pre-EQ** tap switching, **Slow / Fast** ballistics (`0.89` / `0.74` analyser smoothing and `8` / `14 dB/s` decay), and a true **1000 ms Peak Hold** envelope.
* **AutoEQ Excluded for MIRE**: Automated AutoEQ solver controls are disabled in both `eqPanel.js` and `equalizer.js` to avoid inappropriate coupler-style auto-fitting on open-canal MIRE data.

### 17. Modular Floating Music Player (`musicPlayer.js`)
* **Shared Audio-Bridge Routing (`window.mireAudioBridge`)**: Built as a self-contained, desktop-only (`> 1000px`) floating window—supporting both full playlist view and a collapsed mini transport bar—that routes local playback directly through MIRElink's Web Audio chain (Parametric EQ, Perceptual Auto-Gain, Channel Balance, and real-time FFT Spectrum Analyzer) without coupling to core graphing code.
* **Zero-Copy Local Library Persistence & One-Click Reconnect**: Stores lightweight track metadata and Chromium File System Access API file/folder handles in IndexedDB rather than copying audio blobs into browser storage. When browser restarts reset handle permissions, a header **`Reconnect`** control restores read access across stored handles in one step (with folder/file re-link fallback on browsers without persistent handle APIs).
* **In-Browser Metadata Tag & Codec Parsing**: Parses embedded headers directly from local audio files (`ID3v1/ID3v2`, `FLAC` Vorbis comments, `OGG/Opus`, `MP4/M4A` atoms, `WAV`, and `AIFF`, with encoding fallbacks) to extract `Title`, `Artist`, `Album Artist`, `Album`, `#`, `Codec`, `Bitrate`, and `Duration`—supporting custom playlists, instant metadata search, resizable columns, drag-to-reorder column preferences, and combined single-line tag columns (`Title / Artist`, `Artist / Album`, `Album Artist / Album`).
* **On-Demand Single Cover Art (Zero Art Caching)**: To prioritize leanness and table scrolling responsiveness on large libraries, album art is never pre-decoded or stored across the track list. Artwork is extracted on demand solely for the currently playing track in the bottom transport bar and its `ObjectURL` is immediately revoked whenever playback switches or stops.

## 3. User Guide & REW Export Reminder

### Exporting REW Measurements
1. Take measurements in REW (typically 3 seatings per ear: `L1..L3` and `R1..R3`).
2. Apply **1/6-octave acoustic smoothing**.
3. Apply Left and Right **DF-HRTF compensation**.
4. Export as text (`.txt`, tab/space separated): **File $\rightarrow$ Export $\rightarrow$ Export measurement as text**.

### Filename Standard
Format: `[Brand] [Model] [Glass or Variant] [Channel][Seating].txt`

* Clean Seal: `Sony MDR-MV1 L1.txt`
* Eyeglasses Seal: `Sony MDR-MV1 G L1.txt`
* Multi-Word Brand: `Audio Technica ATH R50x L1.txt`
* Mode / Pad Variant Tag: `Loewe Leo (ANC 100) R3.txt` (both `Model G (Mode)` and `Model (Mode) G` are supported)

Upload `.txt` files directly into the **`/data/`** directory on GitHub to automatically build the phonebook.
